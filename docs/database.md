# دیتابیس: PostgreSQL

## انتخاب

دیتابیس پروژه **PostgreSQL** است (تصمیم مالک پروژه): استاندارد صنعتی، مناسب چند کیوسک هم‌زمان و رشد آینده (پنل ادمین، گزارش‌گیری، چند شعبه)، با ابزارهای پشتیبان‌گیری و مدیریت دسترسی حرفه‌ای. برنامه روی **سیستم میزبان** با PostgreSQL حرف می‌زند؛ کیوسک‌ها هرگز مستقیم به دیتابیس وصل نمی‌شوند ([`deployment.md`](deployment.md)).

نیازمندی: PostgreSQL ۱۴ یا بالاتر، Node ۲۰٫۹ یا بالاتر (نیازمندی Next.js ۱۶).

## وضعیت تأیید (صادقانه)

| بخش | وضعیت |
|---|---|
| خودآزمایی `/api/dev/db-check?e2e=1` روی **PostgreSQL ۱۸٫۶ (ویندوز)** | ✅ هر ۱۲ بررسی گذشت: مهاجرت، داده‌ی اولیه، قالب تاریخ/ساعت، شمارنده‌ی ۲۰ درخواست موازی، rollback، ساخت هم‌زمان بیمار، یکتایی‌ها، و (e2e) ۱۵ بیمار موازی، ۵ ثبت موازی یک بیمار، ۵ ارسال با `requestId` یکسان، سقف روزانه |
| منطق کسب‌وکار و SQL مشترک | ✅ ۲۸ تست خودکار روی موتور جایگزین با همان API اتصال |
| رابط کیوسک (کل جریان‌ها، تایمرها، هشدار بی‌فعالیتی، بسته‌شدن خودکار قبض، بازگشت/انصراف، پاسخ نامعتبر API) | ✅ ۱۶ سناریو در Chromium واقعی با React 19 و API ساختگی |
| `next build` و اجرای کامل پروژه (Tailwind، فونت‌ها، ظاهر نهایی) | ⚠️ در محیط ساخت اجرا نشده؛ با `npm run build` و دیدن صفحه‌ها تأیید شود |

## راه‌اندازی

### گزینه‌ی الف: نصب مستقیم روی ویندوز (ساده‌ترین)

1. از postgresql.org نسخه‌ی ویندوز را دانلود و نصب کنید. پورت `5432` را نگه دارید، برای کاربر `postgres` یک رمز بگذارید و آن را یادداشت کنید (pgAdmin هم همراه نصب می‌شود).
2. از منوی Start برنامه‌ی **SQL Shell (psql)** را باز کنید. با Enter همه‌ی پرسش‌ها را قبول کنید (فقط رمز `postgres` را بنویسید) و این دو دستور را اجرا کنید:

```sql
CREATE USER kiosk_app WITH PASSWORD 'یک_رمز_قوی_بدون_کاراکتر_خاص';
CREATE DATABASE kiosk OWNER kiosk_app;
```

### گزینه‌ی ب: Docker

فایل `docker-compose.yml` را در ریشه‌ی پروژه بسازید (نمونه در پیام راهنما) و `docker compose up -d` بزنید. داده در یک volume ماندگار می‌ماند.

### اتصال برنامه

1. `npm install pg` و `npm install -D @types/pg`
2. فایل `.env.local` در ریشه‌ی پروژه (در گیت نمی‌رود):

```env
DATABASE_URL=postgres://kiosk_app:رمز@localhost:5432/kiosk
```

3. `npm run dev`. با اولین درخواست، جدول‌ها ساخته و داده‌ی اولیه وارد می‌شود (نیازی به دستور جدا نیست).

> رمز را بدون کاراکترهای خاص (`@ : / # ?`) بگذارید؛ وگرنه باید در `DATABASE_URL` کدگذاری شود.

## خودآزمایی

با برنامه‌ی در حال اجرا (`npm run dev`) در مرورگر باز کنید:

| آدرس | چه می‌کند |
|---|---|
| `/api/dev/db-check` | اتصال، نسخه‌ی مهاجرت، داده‌ی اولیه، قالب تاریخ/ساعت، شمارنده‌ی هم‌زمان (۲۰ درخواست موازی)، rollback، ساخت هم‌زمان بیمار، محدودیت‌های یکتایی. فقط با داده‌ی ساختگی (`2099-01-01`) کار می‌کند و پاک‌سازی می‌کند |
| `/api/dev/db-check?e2e=1` | علاوه بر بالا، **خود ثبت نوبت** را زیر فشار هم‌زمان می‌آزماید: ۱۵ بیمار موازی (شماره‌ها پشت سر هم)، ۵ ثبت موازی یک بیمار (فقط ۱ موفق)، ۵ ارسال با `requestId` یکسان (یک نوبت)، سقف روزانه. باید در ساعتی اجرا شود که حداقل یک پزشک در ساعت حضورش است. نوبت‌های آزمایشی پاک و شمارنده به حالت قبل برمی‌گردد |

خروجی JSON است و `allOk: true` یعنی همه‌چیز درست. این مسیر در حالت production (`npm start`) غیرفعال است.

## ساختار فایل‌ها

```text
lib/db/
  connection.ts    ← pool اتصال، query، withTransaction، advisoryLock
  migrations.ts    ← ساختار جدول‌ها (نسخه‌بندی‌شده، جدول schema_migrations)
  seed.ts          ← داده‌ی اولیه از data/kiosk-data.ts (فقط وقتی دیتابیس خالی است)
  crypto.ts        ← hash و رمزنگاری کد ملی/موبایل
  repositories.ts  ← همه‌ی کوئری‌های SQL
  self-check.ts    ← خودآزمایی (فقط توسعه)
storage/secret.key ← کلید رمزنگاری هویت (در گیت نمی‌رود)
```

سرویس‌ها (`lib/kiosk/*`) SQL نمی‌نویسند و همه‌ی توابع‌شان `async` است.

## جدول‌ها

| جدول | محتوا |
|---|---|
| `specialties`، `doctors` | تخصص و پزشک |
| `doctor_schedules` | برنامه‌ی هفتگی (`weekday` ۰ تا ۶، `TIME`، اعتبار `DATE` از/تا) |
| `schedule_exceptions` | غیبت (`disabled`) یا ساعت جایگزین (`override`)؛ حداکثر یک استثنای فعال برای هر پزشک در هر روز |
| `patients` | بیمار؛ کد ملی و موبایل فقط hash و رمزنگاری‌شده |
| `appointments` | نوبت (`DATE`، `TIME`، `status`، `request_id`) |
| `daily_counters` | شمارنده‌ی روزانه‌ی هر پزشک |
| `schema_migrations` | نسخه‌های اجراشده‌ی ساختار |

قواعدی که **خود دیتابیس** تضمین می‌کند: شماره‌ی تکراری برای (تخصص، پزشک، روز) · یک نوبت فعال برای هر (بیمار، پزشک، روز) (ایندکس یکتای جزئی) · `request_id` یکتا · وضعیت‌های مجاز · روز هفته ۰ تا ۶ · پایان بعد از شروع · کلیدهای خارجی.

## هم‌زمانی چند کیوسک

هر ثبت نوبت یک تراکنش است و این محافظ‌ها را دارد:

| خطر | محافظ |
|---|---|
| دو بیمار شماره‌ی یکسان بگیرند | ردیف شمارنده با `INSERT … ON CONFLICT DO UPDATE … RETURNING` قفل می‌شود |
| یک بیمار هم‌زمان دو بار ثبت کند یا از سقف روزانه رد شود | `pg_advisory_xact_lock` روی هویت (hash) بیمار، قبل از ساخته شدن بیمار |
| یک درخواست دو بار ارسال شود (تلاش دوباره) | `pg_advisory_xact_lock` روی `requestId` + ستون یکتای `request_id` |
| قفل به هر دلیل کار نکند | ایندکس‌های یکتای دیتابیس پشتوانه‌اند و خطا می‌دهند، نه داده‌ی اشتباه |
| خطا وسط کار | rollback کامل (شماره‌ی مصرف‌شده هم برمی‌گردد) |

## هویت بیمار (کد ملی و موبایل)

هیچ کد ملی یا موبایلی به‌صورت متن ساده ذخیره نمی‌شود: `*_hash` (HMAC-SHA256) برای جستجو و `*_enc` (AES-256-GCM) برای نمایش در پنل ادمین.

- کلید: متغیر `KIOSK_DATA_KEY` (۶۴ کاراکتر هگز) یا فایل `storage/secret.key` که در اولین اجرا خودکار ساخته می‌شود.
- ⚠ **بدون کلید، بیماران قابل جستجو و رمزگشایی نیستند.** کلید را **جدا از** پشتیبان دیتابیس نگه دارید.

## پشتیبان‌گیری و بازیابی

```bash
# پشتیبان
pg_dump -U kiosk_app -h localhost -F c -f kiosk-backup.dump kiosk
# بازیابی (روی دیتابیس خالی)
pg_restore -U kiosk_app -h localhost -d kiosk kiosk-backup.dump
```

پشتیبان را همراه **کپی جداگانه‌ی `secret.key`** نگه دارید. در مرحله‌ی استقرار، اجرای خودکار روزانه تنظیم می‌شود. «پشتیبانی که بازیابی نشده، پشتیبان نیست»؛ یک بار بازیابی را آزمایش کنید.

## ریست دیتابیس (برای توسعه)

```sql
-- در psql، روی دیتابیس kiosk
DROP SCHEMA public CASCADE;
CREATE SCHEMA public;
```
با اجرای بعدی برنامه، همه‌چیز از اول ساخته و seed می‌شود.

## تغییر ساختار

هرگز مهاجرت قدیمی را ویرایش نکنید؛ یک عضو تازه به انتهای آرایه‌ی `MIGRATIONS` اضافه کنید. `data/kiosk-data.ts` فقط روی دیتابیس **خالی** اثر دارد.

## عیب‌یابی

| پیام | علت |
|---|---|
| «متغیر DATABASE_URL تنظیم نشده» | `.env.local` ساخته نشده یا بعد از ساخت، سرور dev دوباره اجرا نشده |
| «راه‌اندازی دیتابیس PostgreSQL انجام نشد … ECONNREFUSED» | سرویس PostgreSQL روشن نیست یا پورت/نشانی اشتباه است |
| «password authentication failed» | نام کاربری یا رمز در `DATABASE_URL` اشتباه است |
| «permission denied for schema public» | کاربر مالک دیتابیس نیست؛ `CREATE DATABASE kiosk OWNER kiosk_app` را دوباره بررسی کنید |
