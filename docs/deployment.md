# استقرار و معماری سخت‌افزار

> این سند برای تصمیم‌گیری درباره‌ی سرور، شبکه، چاپگر و خرید سخت‌افزار است. ساده نوشته شده تا بدون پیش‌زمینه‌ی فنی هم قابل استفاده باشد.

## ۱) معماری پیشنهادی

```text
                      شبکه‌ی داخلی کلینیک (بدون نیاز به اینترنت)

   ┌──────────────┐        ┌──────────────┐        ┌──────────────┐
   │  کیوسک ۱      │        │  کیوسک ۲      │        │  کیوسک ۳ …    │
   │ کامپیوتر +    │        │ کامپیوتر +    │        │              │
   │ مانیتور لمسی  │        │ مانیتور لمسی  │        │              │
   │ فقط Chrome    │        │ فقط Chrome    │        │              │
   └──────┬───────┘        └──────┬───────┘        └──────┬───────┘
          │  فقط صفحه‌ی کیوسک و درخواست‌های ثبت/جستجو      │
          └────────────────────┬──────────────────────────┘
                               ▼
                 ┌───────────────────────────┐
                 │   سیستم میزبان (سرور)       │
                 │   • برنامه‌ی Next.js        │   ← پنل ادمین از همین سیستم
                 │   • دیتابیس PostgreSQL     │      (یا از IP مجاز) باز می‌شود
                 │   • نسخه‌ی پشتیبان روزانه    │
                 └───────────────────────────┘
```

این همان ایده‌ی «سیستم مجزا به‌عنوان هاست، با کیوسک‌هایی که هرکدام سیستم خودشان را دارند» است.

### نقش هر بخش

| بخش | چه می‌کند | چه چیزی **ندارد** |
|---|---|---|
| **سرور** | برنامه، دیتابیس، ساعت مرجع، منطق شماره‌دهی، پنل ادمین، پشتیبان‌گیری | — |
| **کیوسک** | مرورگر Chrome تمام‌صفحه که صفحه‌ی سرور را نشان می‌دهد؛ چاپ (بسته به انتخاب بخش ۵) | دیتابیس، کد برنامه، اطلاعات بیماران |

مزیت اصلی: اگر کیوسکی دزدیده یا خراب شود، **هیچ اطلاعاتی روی آن نیست**. نصب و به‌روزرسانی هم فقط روی یک سیستم انجام می‌شود (سرور)، نه روی هر کیوسک.

## ۲) امنیت: چند لایه

| لایه | اقدام |
|---|---|
| **شبکه** | سرور و کیوسک‌ها در یک شبکه‌ی داخلی بسته؛ سرور از اینترنت بیرونی قابل دسترس نباشد. IP ثابت برای سرور |
| **دیتابیس** | فقط خود برنامه روی همان سرور به آن وصل شود؛ پورت دیتابیس روی شبکه باز نباشد؛ رمز قوی در فایل `.env` (در گیت نرود) |
| **کیوسک مجاز** | هر کیوسک یک بار از پنل ادمین «ثبت و جفت» می‌شود و یک شناسه‌ی مخفی می‌گیرد؛ APIهای کیوسک فقط برای کیوسک‌های جفت‌شده کار می‌کنند. کیوسک گم‌شده از پنل غیرفعال می‌شود |
| **پنل ادمین** | ورود با نام کاربری و رمز، **و** فقط از سیستم میزبان یا IPهای مجاز؛ کیوسک‌ها هرگز به `/admin` دسترسی ندارند (حتی اگر کسی آدرسش را بداند) |
| **اطلاعات بیمار** | کد ملی در دیتابیس رمزنگاری می‌شود (برای نمایش در ادمین) و یک نسخه‌ی hash برای جستجو دارد؛ لاگ‌ها بدون کد ملی و موبایل |
| **ویندوز/لینوکس کیوسک** | کاربر عادی بدون دسترسی مدیر؛ ورود خودکار؛ Chrome در حالت `--kiosk`؛ بستن USB و کلیدهای میانبر در حد امکان |
| **پشتیبان** | نسخه‌ی روزانه روی دیسک دیگر + نسخه‌ی هفتگی بیرون از کلینیک (فلش یا سیستم دیگر) |

## ۳) دیتابیس: PostgreSQL

**PostgreSQL روی سیستم میزبان** (تصمیم مالک پروژه). جزئیات راه‌اندازی، هم‌زمانی، پشتیبان‌گیری و خودآزمایی: [`database.md`](database.md).

| دلیل | توضیح |
|---|---|
| چند کیوسک هم‌زمان | تراکنش، قفل ردیف و قفل سبک (advisory lock) تضمین می‌کنند شماره یا نوبت تکراری ساخته نشود |
| رشد | پنل ادمین، گزارش‌گیری، چند شعبه |
| امنیت | کاربر جدا با دسترسی محدود؛ دیتابیس فقط از خود برنامه در دسترس است |
| ابزار | `pg_dump` و `pg_restore` برای پشتیبان‌گیری؛ pgAdmin برای مشاهده |

> دیتابیس باید **فقط از خود سیستم میزبان** قابل دسترس باشد (`localhost`)، نه از شبکه‌ی کیوسک‌ها.

## ۴) شبکه و سرور

| مورد | توصیه |
|---|---|
| سرور | یک mini PC یا کامپیوتر با SSD، حداقل ۸ گیگابایت RAM؛ همیشه روشن |
| برق | **UPS** برای سرور (و ترجیحاً کیوسک‌ها)؛ قطع ناگهانی برق بزرگ‌ترین خطر برای دیتابیس است |
| شبکه | سوئیچ/روتر کابلی (LAN)؛ کابل بهتر از Wi-Fi برای کیوسک و سرور |
| آدرس | IP ثابت برای سرور (مثلاً `192.168.1.10`)؛ کیوسک‌ها `http://192.168.1.10:3000` را باز می‌کنند |
| ساعت | ساعت سرور باید درست باشد (همه‌ی زمان‌ها از سرور می‌آید). همگام‌سازی خودکار ساعت (NTP) فعال باشد و منطقه‌ی زمانی تهران تنظیم شود |
| اینترنت | برای کار روزمره لازم نیست |

## ۵) چاپگر قبض (تصمیم مهم قبل از خرید)

چون صفحه‌ی نوبت باید در ۵ ثانیه بسته شود و در صورت خرابی چاپ، سیستم باید بداند:

| گزینه | چطور کار می‌کند | مزیت | عیب |
|---|---|---|---|
| **الف) چاپگر شبکه‌ای (LAN)، چاپ از سرور** | سرور بعد از ثبت نوبت مستقیم به چاپگر دستور می‌دهد | **وضعیت چاپ را می‌داند** (کاغذ تمام شده؟)، روی کیوسک چیزی نصب نمی‌شود | چاپگر باید پورت شبکه و پشتیبانی ESC/POS داشته باشد؛ IP ثابت می‌خواهد |
| **ب) چاپگر USB روی هر کیوسک، چاپ از Chrome** | Chrome با `--kiosk-printing` بی‌صدا چاپ می‌کند | ساده، با چاپگرهای معمولی ارزان کار می‌کند | **از موفق یا ناموفق بودن چاپ خبری نیست** |

**توصیه: گزینه‌ی الف.** هنگام خرید به این مشخصات دقت کنید: **«چاپگر حرارتی ۸۰ میلی‌متری»، «پورت شبکه (Ethernet/LAN)»، «پشتیبانی ESC/POS»، «برش‌دهنده‌ی خودکار (auto-cutter)».** اگر تصمیم دیگری گرفتید، تغییرش فقط بخش چاپ را عوض می‌کند، نه بقیه‌ی برنامه را.

## ۷) عملیات روزمره

| کار | چطور |
|---|---|
| راه‌اندازی خودکار برنامه | برنامه به‌صورت سرویس اجرا شود تا با روشن شدن سرور خودش بالا بیاید |
| راه‌اندازی خودکار کیوسک | ورود خودکار کاربر + Chrome با `--kiosk` در استارت‌آپ |
| پشتیبان‌گیری | روزانه خودکار با `pg_dump` (دیتابیس **و** `secret.key` جدا از هم) + آزمایش بازیابی دست‌کم یک بار (پشتیبانی که بازیابی نشده، پشتیبان نیست) |
| به‌روزرسانی | فقط روی سرور؛ کیوسک‌ها با رفرش خودکار نسخه‌ی جدید را می‌گیرند |
| نظارت | پنل ادمین وضعیت هر کیوسک (آخرین ارتباط) را نشان دهد |

## ۹) تصمیم‌های باز
- سیستم‌عامل سرور (ویندوز یا لینوکس): فعلاً روی سیستم توسعه‌دهنده اجرا می‌شود؛ تا خرید سخت‌افزار اهمیتی ندارد.
- چاپگر: الف یا ب (بخش ۵)، پیش از خرید.
- تعداد کیوسک‌ها: روی طراحی اثری ندارد، فقط روی خرید.
