# سیستم طراحی کیوسک نوین دیدگان

> ممیزی وضعیت قبلی، سیستم جدید و مستند کامپوننت‌ها. اعداد ممیزی با `grep` روی کد قبلی و جدید شمارش شده‌اند.

**۱۷ کامپوننت بررسی شد.** امتیاز تقریبی (ارزیابی خودم، نه معیار رسمی): **۳۵ از ۱۰۰**

### یکپارچگی نام‌گذاری و پیاده‌سازی

| مشکل | کجا | اقدام |
|---|---|---|
| ۲۰ تگ `<button>` خام در ۱۱ فایل، بدون کامپوننت Button مشترک | همه‌ی صفحه‌ها | کامپوننت `Button` با ۳ واریانت |
| ۴ شعاع گوشه برای کارت‌ها (`2rem`، `3xl`، `1.75rem`، `2xl`) | کارت‌های انتخاب | دو توکن: `card` و `control` |
| ۴ پیاده‌سازی متفاوت کارت انتخاب (`KioskCard`، `KioskChoice`، و دکمه‌ی خام در ملیت، تخصص، پزشک، جراحی). دو مورد اول اصلاً استفاده نمی‌شدند | `components/kiosk` | یک `ChoiceCard` |
| فرم کد ملی و موبایل: ۴۷۶ خط با منطق یکسان (نرمال‌سازی ارقام، تأخیر راهنما، پیام‌ها) | `NationalIdForm`، `MobileForm` | یک `DigitEntryForm` (۱۵۳ خط) و دو پوسته‌ی ۲۰ خطی |

### پوشش توکن

| دسته | تعریف‌شده | یافته‌ی هاردکد |
|---|---|---|
| رنگ | دو سیستم موازی (`--kiosk-*` با ۹ متغیر و `novin*` با ۱۰ متغیر) با مقادیر تکراری (`#01a9ea` و `#012676` هر کدام دو بار) | ۶ hex در TSX |
| نوشتار | هیچ مقیاس تعریف‌شده‌ای نبود | ۳ مورد زیر ۱۲px، ۱۵ مورد `text-sm`/`text-xs` |
| فونت | ۸ فونت لود می‌شد | فقط ۳ تا واقعاً استفاده می‌شد (آقاسم، میخک Bold، میخک Medium) |
| کنتراست | — | ۲۱ مورد متن `text-white/45` تا `/65` روی پس‌زمینه‌ی تیره (۳ مورد `/45` ≈ ۴.۲:۱، زیر حد ۴.۵:۱ برای متن معمولی) |

### کامل بودن حالت‌ها

| کامپوننت | حالت‌ها | وضعیت |
|---|---|---|
| NumericKeypad | disabled، loading | دکمه‌ی «تایید» دایره‌ی ۷۲px با متن ۱۴px؛ ارقام لاتین در کیبورد ولی فارسی در فیلد |
| صفحه‌های بارگذاری | loading | متن ساده؛ یک جا با `class` غلط (`tetx-xl`) |
| صفحه‌های خطا | error | «تلاش مجدد» کل صفحه را reload می‌کرد و مراحل پاک می‌شد |
| صفحه‌ی بارگذاری ثبت نوبت | loading | دکمه‌ی «بازگشت به صفحه شروع» داشت؛ پاسخ دیرهنگام به کاربر بعدی می‌رسید |

### اولویت‌های اجرا‌شده
1. توکن‌های واحد و حذف دو سیستم رنگ موازی
2. کامپوننت‌های پایه (Button، ChoiceCard، Screen، StatusPanel)
3. بازطراحی ورود عدد (کیبورد و فیلد خانه‌ای)
4. حذف پس‌زمینه‌ی متحرک سنگین

| توکن | اندازه | کاربرد |
|---|---|---|

| `text-title` | ۲۸px | عنوان کارت، دکمه‌ی بزرگ |
| `text-heading` | ۳۰ تا ۴۲px (واکنش‌گرا) | عنوان صفحه |

`rounded-card` (۲۴px) برای کارت‌ها، `rounded-control` (۱۶px) برای دکمه و فیلد، `shadow-card` برای سطح‌ها، `shadow-lift` فقط برای عمل اصلی.

### لمس
حداقل ارتفاع دکمه ۶۴px (`md`) و ۸۰px (`lg`)؛ کلیدهای کیبورد ۸۰px.

## ۴) کامپوننت‌ها

### Button
| واریانت | چه زمانی |
|---|---|
| `primary` | عمل اصلی صفحه (حداکثر یکی در هر صفحه) |
| `secondary` | عمل مکمل، مثل «بازگشت» |
| `quiet` | خروج، مثل «انصراف» |

| حالت | رفتار |
|---|---|
| default / فشرده | `active:scale` و تغییر رنگ (به‌جای hover که روی لمس معنا ندارد) |
| disabled | شفافیت ۴۵٪، غیرفعال |
| loading | اسپینر، غیرفعال |

**دسترس‌پذیری:** نقش `button` بومی؛ حلقه‌ی فوکوس ۴px برای صفحه‌کلید فیزیکی.

### ChoiceCard
کارت قابل لمس برای انتخاب. `variant="featured"` برای گزینه‌ی پیشنهادی (حداکثر یکی)، `size="compact"` برای فهرست‌های چندتایی. انتخاب بلافاصله به مرحله‌ی بعد می‌رود، پس حالت «انتخاب‌شده» ندارد.

### Screen
قالب همه‌ی مرحله‌ها: عنوان راست‌چین ← محتوا ← ناوبری ثابت پایین. جای «بازگشت» و «انصراف» در تمام صفحه‌ها یکسان است.

### KioskProgress
تیک سبز = انجام‌شده، دایره‌ی پر آبی = مرحله‌ی فعلی، دایره‌ی توخالی = بعدی. رنگ تنها حامل معنا نیست. متن مخفی `مرحله ۲ از ۴` برای صفحه‌خوان.

### DigitEntryForm، DigitField، NumericKeypad
- فیلد خانه‌ای با گروه‌بندی (کد ملی ۳-۳-۴، موبایل ۴-۳-۴)؛ خانه‌ی بعدی پررنگ می‌شود.
- کیبورد ۱۲ کلیدی با ارقام فارسی؛ «تأیید» دکمه‌ی بزرگ جدا زیر آن.
- در صفحه‌ی عریض، فیلد و کیبورد کنار هم می‌نشینند تا ارتفاع کم شود.
- پیام وضعیت `aria-live="polite"`.

### StatusPanel
سه حالت `loading`، `error`، `empty`. ساختار هر پیام: **چه شد ← چرا یا چه کنیم ← دکمه‌ی راه‌حل**.

### IdleWarning
۳۰ ثانیه پیش از ریست خودکار ظاهر می‌شود. تا لمس «ادامه می‌دهم»، لمس‌های دیگر نادیده‌اند (تا لمسِ بستن به دکمه‌ی زیرین نشت نکند).

## ۵) قواعد

| ✅ انجام بده | ❌ انجام نده |
|---|---|
| فقط از توکن‌ها استفاده کن | hex یا مقدار دلخواه در کامپوننت |
| در هر صفحه یک عمل `primary` | دو دکمه‌ی آبی توپر کنار هم |
| رنگ + آیکن + متن برای وضعیت | وضعیت فقط با رنگ |
| `iris` فقط برای تزئین | `iris` برای متن (کنتراست ناکافی) |
| `active:` برای بازخورد لمس | وابستگی به `hover` |

## ۶) سؤال‌های باز
- آیا صفحه‌ی نمایش فقط افقی است یا کیوسک عمودی هم داریم؟ (چیدمان دو ستونه‌ی ورود عدد برای افقی بهینه است.)
- بعد از وصل شدن چاپگر، متن صفحه‌ی موفقیت باید به «قبض شما چاپ شد» تغییر کند.
- پس‌زمینه‌ی تیره‌ی قبلی برای سالن با نور کم انتخاب شده بود؟ اگر بله، تم تیره‌ی همین توکن‌ها را می‌توان اضافه کرد.

## ۷) نهایی‌سازی (پس از آزمون روی صفحه‌ی ۱۵ اینچ)

| تغییر | جزئیات |
|---|---|
| صفحه‌ی کم‌ارتفاع | `@custom-variant short (@media (max-height: 900px))`. با F11 ارتفاع قابل‌استفاده فرق می‌کند، پس آستانه از ۸۲۰ به ۹۰۰ رفت |
| هدر | بیرون از کانتینر محتوا؛ لوگو و لوگوتایپ گوشه‌ی راست، ساعت گوشه‌ی چپ؛ لوگو در همه‌ی صفحه‌ها بزرگ می‌ماند (`size-16`، و در صفحه‌ی کم‌ارتفاع `size-14`) |
| ساعت | با ثانیه‌شمار، تا بیماری که منتظر ایستاده مطمئن شود سیستم کار می‌کند |
| عرض محتوا | `max-w-7xl` به‌جای `max-w-6xl` |
| پنجره‌ی بی‌فعالیتی | دکمه‌ی «انصراف و پاک کردن اطلاعات» برای بیمار بعدی |
| صفحه‌ی نوبت | چیدمان افقی (شماره کنار جزئیات)، بدون دکمه‌ی «پایان»، بسته‌شدن خودکار در ۵ ثانیه، نوار شمارش معکوس (`.drain`)، نوار مراحل پنهان |
| کارت تخصص | تعداد پزشکان حاضر («۳ پزشک حاضر»)؛ این عدد **پزشکان حاضر** است نه طول صف |
